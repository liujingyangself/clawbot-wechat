# 常见问题

遇到问题先看这里。每一条都写了「你会看到什么」和「怎么办」。

## 安装的时候

### Mac：双击提示「无法打开，因为无法验证开发者」

**怎么办**：右键点那个文件 → 选「打开」→ 在弹出的框里再点一次「打开」。
只需要做这一次，以后双击就行。

### Windows：提示「此应用无法在你的电脑上运行」或者一闪而过

**注意**：**不要以管理员身份运行！** 所有组件和服务都必须装在当前登录用户的目录下。如果以管理员身份运行，后台计划任务会注册到 Administrator 账户，导致读取不到你的微信和 Antigravity 登录凭据，微信完全收不到消息。

**怎么办**：
1. 直接在开始菜单搜「PowerShell」打开（普通权限即可）。
2. 粘贴下面这条命令回车，放开当前用户的脚本执行权限：
   ```powershell
   Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
   ```
3. 然后直接双击 `安装-Windows.bat`。

### Windows：PowerShell 报红字语法错误（`TerminatorExpectedAtEndOfString` / `UnexpectedToken`）

**你会看到什么**：终端报类似 `The string is missing the terminator: '` 或 `Unexpected token ... in expression or statement`。

**原因**：Windows 10/11 内置的 PowerShell 5.1 在中文系统（GBK/CP936 代码页）下，如果脚本是「不带 BOM 的 UTF-8」编码，汉字的多字节编码会与单双引号冲突，导致语法解析崩溃。

**怎么办**：
- 本仓库代码已全量采用 **UTF-8 with BOM** 编码。请拉取仓库最新版本，或者用 VS Code / 记事本打开脚本，选择「通过编码保存」→「UTF-8 with BOM」。
- 若使用一行安装命令，请重新执行：
  ```powershell
  irm https://raw.githubusercontent.com/liujingyangself/clawbot-wechat/main/get.ps1 | iex
  ```

### 密钥粘贴后提示「格式不像」或校验失败（`AQ.` 开头的密钥）

**你会看到什么**：提示「格式不像（应该以 AIza 开头、很长一串）」。

**原因**：Google AI Studio 新生成的 API 密钥采用了 `AQ.` 开头（例如 `AQ.xxxxxxxx…（这里是示例）`），而旧版脚本仅认 `AIza` 开头。

**怎么办**：
- 最新版脚本已全面支持 `AIza` 与 `AQ.` 前缀。
- 如果需要手动设置密钥，可以在 PowerShell / 终端中直接运行：
  ```bash
  openclaw config set models.providers.google "{\"apiKey\":\"你的密钥\"}" --strict-json --merge
  ```

### 微信扫码窗口没弹出来 / 二维码过期 / 字符二维码乱码错位

**你会看到什么**：提示「正在弹出一个新窗口：微信扫码登录」，但桌面上没有看到弹窗；或者终端里的 ASCII 字符二维码因字体原因扭曲扫不上；或者因离开过久导致二维码失效（二维码有效期约 8 分钟）。

**怎么办**：
1. **最快捷做法**：双击根目录下的 **`扫码登录-Windows.bat`**（Mac 为 **`扫码登录-Mac.command`**），它会直接启动专属前台控制台进行微信扫码登录，**不需要重新跑一遍安装流程**！
2. **命令行直接扫码**：在终端运行：
   ```bash
   openclaw channels login --channel openclaw-weixin
   ```
3. **微信内直链打开**：命令行输出中会打印一行类似下面的登录直链：
   ```text
   https://liteapp.weixin.qq.com/q/xxxxxx?qrcode=...&bot_type=3
   ```
   你可以把该链接直接发送到手机微信对话中，点击链接即可直接在微信内完成一键授权登录！

### 安装时提示「正在弹出一个新窗口：Antigravity 登录」，但桌面上没有看到弹窗（后台无界面挂起）

**你会看到什么**：终端显示「正在弹出一个新窗口：Antigravity 登录」，但显示器屏幕上没有任何新窗口跳出来，脚本停滞在原地等待。

**原因**：如果安装命令是由 **AI 编码助手（如 Cursor / Claude / Antigravity）** 或 IDE 内置无界面终端拉起的，Windows 会默认以后台非交互沙箱（Headless）启动子进程，导致 `powershell.exe` 创建的子控制台无法挂载到前台物理桌面上，进而在后台盲等用户输入。

**怎么办**：
1. **直接跳过即可**：Antigravity CLI（`agy`）仅作为日常写代码、改文件等「干重活」的辅助工具。**日常微信聊天直接走免费的 Gemini 通道，完全不依赖它！** 按 `Ctrl + C` 退出或跳过不影响使用。
2. **前台单独登录**：直接在桌面开始菜单打开一个全新的 **PowerShell** 窗口，输入 `agy` 并回车，在真实前台窗口中完成一次浏览器授权。
3. **一行命令静默补齐**：在项目目录下执行以下命令，无需弹出任何界面即可直接完成配置与权限加固：
   ```powershell
   $onboard = Join-Path $env:USERPROFILE '.gemini\antigravity-cli\cache\onboarding.json'
   New-Item -ItemType Directory -Force -Path (Split-Path $onboard) | Out-Null
   '{"consumerOnboardingComplete":true,"enterpriseOnboardingComplete":true,"onboardingComplete":true}' | Set-Content $onboard -Encoding utf8
   & powershell -ExecutionPolicy Bypass -File .\scripts\agy-permissions.ps1
   ```

### Antigravity CLI（`agy`）界面在 Windows 传统控制台按 Enter 或方向键卡死 / 无反应

**你会看到什么**：进入 `agy` 的选配色（Choose your color scheme）或服务条款界面时，按回车 `Enter`、空格、上下方向键 `↑/↓` 没有任何响应，光标不移动，界面甚至出现字符重叠错位。

**原因**：`agy` 采用了全屏原始终端（TUI / Raw Input Mode）技术。Windows 10 自带的旧版 PowerShell 5.1（传统 ConHost 黑色控制台窗口）对 ANSI 终端键盘事件流兼容性较差，按键输入容易被控制台底层消息循环挂起（QuickEdit 模式阻塞或光标丢失）。

**怎么办**：
1. **推荐：按 `Ctrl + C` 退出即可**。日常微信助手聊天完全不受此影响，已经在后台正常运行。
2. **使用现代终端运行**：在 Windows 11 自带或从微软商店免费下载的 **Windows Terminal** 中打开 PowerShell 运行 `agy`。Windows Terminal 原生完整支持 VT100 / ANSI 终端协议，操作极度丝滑，不会卡键。
3. **跳过交互界面**：如需使用，直接通过 `agy -p "你的任务描述"` 单次调用模式执行，无需进入全屏 TUI 引导界面。

### 运行 `irm .../get.ps1 | iex` 时报第一行红字错误（`The term '#' is not recognized...`）

**你会看到什么**：终端首行报红字：
`# : The term '﻿#' is not recognized as the name of a cmdlet, function, script file, or operable program.`

**原因**：PowerShell 的 `Invoke-Expression`（`iex`）在解析带 UTF-8 BOM 头的在线网络脚本流时，将开头的 3 字节 BOM 标记与 `#` 注释符误连成了一个非法的命令名。

**怎么办**：
- **完全无需理会**：此提示仅作用于第一行首字注释，**不影响后续任何实际命令的执行**，安装程序会自动继续往下顺畅下载与安装。
- **去除提示的写法**：若希望完全静默无报错，可在命令中滤去首字符 BOM：
  ```powershell
  (irm https://raw.githubusercontent.com/liujingyangself/clawbot-wechat/main/get.ps1).TrimStart([char]0xFEFF) | iex
  ```

### AI 代理（Cursor / Antigravity / Claude）代跑安装被拦截

**你会看到什么**：提示 `需要在 PowerShell 窗口里运行`。

**原因**：旧版 `get.ps1` 对重定向终端有严格检测。新版 `get.ps1` 已移除该阻断，支持 AI 助手全自动代跑，关键交互步骤会自动调起可视化弹窗供真人扫码与授权。

### 卡在「正在下载安装」很久不动

正常的。OpenClaw 要下载几百兆，网速慢的话十几分钟也可能。
**只要窗口没报错就别关**。真的超过 30 分钟没动静，关掉重新双击一次。

### 提示连不上 Google

你需要能访问 Google 的网络。如果你在中国大陆，先打开你平时用的代理软件，
确认浏览器能打开 google.com，再重新安装。

## 装完之后

### 在微信里发消息，助手不回

按顺序查：

**第一步：服务在跑吗？**

Mac 打开「终端」，Windows 打开 PowerShell，粘这条：

```bash
openclaw gateway status
```

看到 `running` 就是好的。没看到就粘这条重启：

```bash
openclaw gateway restart
```

**第二步：微信连着吗？**

```bash
openclaw channels status
```

要看到 `openclaw-weixin` 而且后面是 `running`。
如果没有，双击 `扫码登录-Windows.bat`（Mac 为 `扫码登录-Mac.command`）重新扫码。

**第三步：是不是没配对？**

助手默认**只理会你批准过的人**。如果是别人给它发消息，它会不理。
看看待批准的有谁：

```bash
openclaw pairing list openclaw-weixin
```

要批准就：

```bash
openclaw pairing approve openclaw-weixin 那串码
```

### 报错：`Provider "google" requires an explicit base URL before using an OpenAI-compatible API`

**你会看到什么**：运行 `openclaw agent --message "你好"` 或微信发消息时，报错提示 `Provider "google" requires an explicit base URL before using an OpenAI-compatible API`，或者日志中出现 `api=openai-responses`。

**原因**：OpenClaw 在为 `models.providers.google` 声明自定义 `models` 数组后，会默认将该 provider 视为 OpenAI 兼容协议，回退至 `openai-responses` 传输并要求显式提供 `baseUrl`。

**怎么办**：必须显式将 `api` 设置为 `google-generative-ai`，并填入官方 `baseUrl`。在终端中执行：

```bash
openclaw config set models.providers.google "{\"api\":\"google-generative-ai\",\"baseUrl\":\"https://generativelanguage.googleapis.com/v1beta\",\"models\":[{\"id\":\"gemini-flash-lite-latest\",\"name\":\"Gemini Flash Lite\",\"api\":\"google-generative-ai\",\"input\":[\"text\"],\"contextWindow\":1000000,\"contextTokens\":200000,\"maxTokens\":8192,\"cost\":{\"input\":0,\"output\":0,\"cacheRead\":0,\"cacheWrite\":0}}]}" --strict-json --merge
openclaw config set agents.defaults.model.primary google/gemini-flash-lite-latest
openclaw gateway restart
```

### 开着 Clash，浏览器能上 Google，但助手说连不上 AI 服务

**这是最常见的一个坑，不是你的错。**

代理软件的「系统代理」模式只对浏览器这类程序有效。助手的后台程序是 Node.js 写的，
它**不读系统代理设置**，所以照样连不上。

安装程序本来会自动探测你的代理端口并配置好。如果还是不行，通常是这几种情况：

1. **代理软件重启后端口变了。** 重新运行一次安装程序，它会重新探测。
2. **你的软件只开了 socks5，没开 HTTP 代理。** 去它的设置里把「HTTP 代理」
   或「混合端口」打开——助手只能用 HTTP 代理，用不了 socks5。
3. **想手动确认配的是哪个端口**，在终端 / PowerShell 里粘：

```bash
openclaw config get proxy.proxyUrl
```

改成别的端口：

```bash
openclaw config set proxy.proxyUrl http://127.0.0.1:你的端口
openclaw gateway install --force
openclaw gateway restart
```

**还有个办法**：把代理软件切到「TUN 模式」或者「虚拟网卡模式」。这个模式接管整台
电脑的所有流量（包括 Node.js），配好之后什么都不用管。缺点是开起来稍微麻烦点。

### 微信消息会不会也被绕到国外去

不会。代理软件是按规则分流的，微信、淘宝这些国内网站在所有主流规则里都是直连，
只有 Google 这类才走代理。所以配了代理不会让你的微信变慢，也不会有额外风险。

### 助手干重活时，用的不是我的 Google 账号

**最容易被忽略的一个坑。**

`agy`（Antigravity 命令行）会**直接沿用这台电脑上 Antigravity 桌面应用的登录态**，
不会再问你。日志里表现为 `silent auth succeeded` —— 全程没有任何人授权过。

> 容易误解的一点：看到「静默认证成功」时，很自然会以为是「这台机器上的 CLI
> 之前登录过」。**不是。** 真正的来源是桌面应用那份登录态。这个区别很重要——
> 它意味着**换一台装过 Antigravity 的电脑给别人用时，对方会继承你的账号**。

所以如果这台电脑以前是别人用的、里面的 Antigravity 登录着别人的 Google 账号，
你的助手就会**静默用着那个人的额度**，而且看不出任何异常。

**怎么确认用的是谁的账号**：

```
openclaw agent --message "用 agy 回复两个字：测试"
```

然后看 Antigravity 的日志，搜 `authenticated successfully as`：

- Windows：`C:\Users\<你的用户名>\.gemini\antigravity-cli\log\` 下最新的 `cli-*.log`
- Mac：`~/.gemini/antigravity-cli/log/` 下最新的 `cli-*.log`

**怎么换成自己的账号**：

1. 打开 **Antigravity** 这个应用
2. 在里面退出登录（Sign out）
3. 用你自己的 Google 账号重新登录
4. 重新运行一次安装程序

> 新版安装器在检测到这台电脑装过 Antigravity 时会主动问你一次，不会再静默沿用。

### Windows：双击 .bat 报「不是内部命令也不是外部命令」

**原因**：批处理文件的编码和 `chcp` 设置对不上。

中文 Windows 的控制台默认是 GBK（代码页 936）。如果一个 `.bat` 文件：

- 存成 **GBK** 编码，却在开头写了 `chcp 65001`（切到 UTF-8），

那么 cmd 在**逐行重新解析**后续内容时就会把中文字节解释错，
轻则乱码，重则把某一行拼成一个不存在的命令 —— 于是报「不是内部命令」。

**两种正确写法，任选其一**：

| 写法 | 文件编码 | 要不要 `chcp 65001` |
|---|---|---|
| A（推荐，兼容性最好） | GBK / ANSI | **不要写** |
| B | UTF-8 | 要写 |

**千万别混搭。** 本仓库的 `.bat` 都是写法 B，自检脚本会检查这一点。

### 通过 SSH 或远程执行时，agy 说没登录（但本机双击就正常）

**这不是故障，是 Windows 的凭据机制。**

Antigravity 的登录凭据和**交互登录会话**绑定（存在凭据管理器 / DPAPI 里，
磁盘上找不到凭据文件）。SSH 属于网络登录，是另一个会话，拿不到这些凭据。

所以：

| 在哪跑 agy | 结果 |
|---|---|
| 本机桌面（双击、或自己开的 PowerShell） | ✅ 正常 |
| SSH / 远程 / 非交互脚本 | ❌ 报没登录、认证超时 |
| **微信助手的后台服务** | ✅ 正常（它的计划任务是交互登录类型，和你桌面同一个会话） |

**所以用 SSH 测出来「没登录」是误报**，不代表微信助手用不了。要验证得让助手自己去调：

```
openclaw agent --message "用 agy 回复两个字：测试"
```

**例外**：如果你用管理员权限装过，计划任务可能注册成了非交互类型，那就真的用不了 agy。
新版安装器会检查并提示。

### 助手回复一串英文报错，里面有 429 或 RESOURCE_EXHAUSTED

**当天的免费次数用光了，不是坏了。**

Google 的免费额度很小：普通 flash **每天只有 20 次**。按这个顺序处理：

**第一步：确认 Antigravity 登录了没有**

这是最可能的原因。Antigravity 用你自己的 Google 账号，额度大得多；
如果安装时跳过了它的登录，助手就只能靠那个每天 20 次的备用通道。

打开终端 / PowerShell，敲：

```bash
agy
```

照提示登录一次（回车选配色 → 空格取消勾选分享数据 → 回车 → 浏览器登录 → 输 `/quit`）。

**第二步：换成额度更大的模型（flash-lite）**

```bash
openclaw config get agents.defaults.model.primary
```

如果显示的不含 `lite`，可以换成 lite 版（免费额度大得多）：

```bash
openclaw config set models.providers.google "{\"api\":\"google-generative-ai\",\"baseUrl\":\"https://generativelanguage.googleapis.com/v1beta\",\"models\":[{\"id\":\"gemini-flash-lite-latest\",\"name\":\"Gemini Flash Lite\",\"api\":\"google-generative-ai\",\"input\":[\"text\"],\"contextWindow\":1000000,\"contextTokens\":200000,\"maxTokens\":8192,\"cost\":{\"input\":0,\"output\":0,\"cacheRead\":0,\"cacheWrite\":0}}]}" --strict-json --merge
openclaw config set agents.defaults.model.primary google/gemini-flash-lite-latest
openclaw gateway restart
```

**第三步：等或者花钱**

- 等 24 小时，免费额度会重置
- 去 https://aistudio.google.com/apikey 开通计费（按量付费，聊天很便宜）

### 我有 Gemini Pro 会员，为什么还会限额

因为 **Pro 订阅和 API 额度是两套完全独立的东西**：

| | Pro 订阅管的 | API key 管的 |
|---|---|---|
| 用在哪 | Gemini 网页版、Antigravity、Google 文档里的 AI | 程序调用 |
| 怎么算钱 | 月费包含 | 按量付费，免费档很小 |

所以 Pro 对那个 API key **不起作用**。

但它对 **Antigravity 起作用** —— 这正是安装时第 1 步让你用 Google 账号登录的原因。
登录了 Antigravity，助手干活才用得上你的 Pro 额度。

### 之前好好的，突然不回消息了

**最常见的原因：电脑睡着了或者关机了。**

这个助手住在你电脑里，电脑不醒着它就不工作。检查一下：

1. 电脑是不是休眠了？（笔记本合盖就会）
2. 网断了吗？
3. 都正常的话，打开终端 / PowerShell 粘这条看看服务还在不在：

```bash
openclaw gateway status
```

没看到 `running` 就粘这条重启：

```bash
openclaw gateway restart
```

**电脑关着的时候别人发的消息，开机后能补上吗？**

不一定。微信服务器那边有个续传机制，重新连上会从上次的位置继续，
但腾讯没有公开说明消息会暂存多久。短时间（几分钟到几小时）通常能收到，
关了好几天就不好说了。**别把它当成留言机用。**

### Windows 后台服务（OpenClaw Gateway）日常管理

OpenClaw 在 Windows 上以计划任务形式常驻运行（任务名称：`OpenClaw Gateway`），监听端口为 `18789`。

常用运维命令：

```powershell
# 查看网关运行状态
openclaw gateway status

# 重启网关服务
openclaw gateway restart

# 查看网关运行日志
openclaw gateway logs

# 检查 18789 端口是否正常监听
netstat -ano | findstr 18789

# 强制重装后台计划任务
openclaw gateway install --force
```

### 助手回得很慢

第一次回话慢是正常的（要加载）。之后一般几秒。
如果一直很慢，可能是免费额度用完了，等一会儿再试。

### 助手说「我没有被允许做这个」

这是故意的保护。它默认只能在**桌面**和**文稿（文档）**里干活，
碰不到系统设置、密码、SSH 密钥这些。

如果你确实需要它动别的地方，让懂技术的朋友改
`~/.gemini/antigravity-cli/settings.json` 里的 `permissions`。

### 群里它不说话

也是故意的。默认在群聊里完全沉默，避免打扰别人、也避免被群里的人骗。

### 画图说没开通

画图要单独开，而且**要花钱**（一张约 1 元）。
Mac 双击 `scripts/添加绘画-Mac.command`，Windows 双击 `scripts\添加绘画-Windows.bat`。

### 画图开通了但报错

一般是计费还没生效，等 5-10 分钟。还不行的话去
https://console.cloud.google.com/billing 确认账单账号已经关联到你创建密钥的那个项目。

## 日志在哪

出问题时把这个文件发给帮你装的人：

- **Mac**：`~/Library/Logs/clawbot-wechat-install.log`
- **Windows**：`%LOCALAPPDATA%\clawbot-wechat\install.log`

Mac 想快速打开这个文件夹，在终端粘：

```bash
open ~/Library/Logs
```

Windows 打开方式：按 `Win + R` 输入 `%LOCALAPPDATA%\clawbot-wechat` 回车。

## 怎么卸载干净

**Mac**，在终端里依次粘这几条：

```bash
openclaw gateway stop
openclaw gateway uninstall
rm -rf ~/.openclaw
rm -rf ~/.gemini/antigravity-cli
rm -f ~/.local/bin/agy
```

**Windows**，在 PowerShell 里：

```powershell
openclaw gateway stop
openclaw gateway uninstall
Remove-Item -Recurse -Force "$env:USERPROFILE\.openclaw"
Remove-Item -Recurse -Force "$env:USERPROFILE\.gemini\antigravity-cli"
```

微信那边不用做什么——卸载后助手就不再登录你的微信了。

另外记得去 https://aistudio.google.com/apikey 把那把密钥删掉。
